在 Bootstrap 升级执行到第 14/26 步时，单独检查日志的中位数为 JS 194.6 ms、Wasm-GC 543.4 ms；同时核对现场 28 条路径后分别为 212.0 ms 和 1465.0 ms。完整发布与单字节漂移的测量见[现场验收基准](checkpoint.md)。

## 运行端到端对照

在含两个版本标签的 Git 仓库根目录运行。脚本使用 Python 3.10+ 标准库，调用同一套 `moon`、`moonrun` 和 Node.js。首次构建需要可用的 MoonBit 依赖，Bootstrap 场景还需能访问 npm 官方注册表。

```sh
python -B benchmarks/review_release.py --baseline v0.7.2 --candidate v0.8.0 --checkpoint --out results.json
```

省略 `--candidate` 会测量当前工作树。在开发机快速重测单个场景可运行以下命令。

```sh
python -B benchmarks/review_release.py --cases docs-10pct-edited --targets js --samples 3 --out sample.json
```

每个版本都单独编译 release 产物，所有输入落在临时目录中。计时从启动新 CLI 进程开始，到收到完整标准输出、标准错误与退出码为止，包含运行时启动、读文件、解析、哈希、规划及 JSON 序列化。构建、生成样本、网络下载、用 Python 检查结果均在计时区间之外。每组先给每个版本预热一次，再默认计时各五次，每轮交换两版本运行顺序。文件系统使用操作系统的自然缓存。

每个样本都检查预期退出码、状态、波次数量与宽度、约束数量和环长度。对同一后端，所有运行的完整标准输出必须逐字节相同且标准错误为空。JS 与 Wasm-GC 的完整 JSON 还要通过结构相等检查。以下输入全部用于真实执行 `review-release --json --before-pages … --after-pages …`。

| 场景 | 两份快照的输入 | 预期计划 |
| --- | --- | --- |
| `docs-10pct-edited` | 各 120 篇不同的文档，各含 30 个表格行和两条本地资源引用。12 篇改变正文，脚本及样式保持相同 | 120 个页面动作，无约束 |
| `docs-100pct-edited` | 与上一组相同的旧站和模板，120 篇均修改正文 | 同上 |
| `shared-2mib` | 12 页共享一个 2 MiB 脚本，原路径变更 1 字节，新页面可接受新旧两个 SHA-512 摘要 | 先切换 12 页，再覆盖脚本 |
| `repeat-64x64` | 64 页各有 64 条重复脚本引用，两份快照合计 8,192 条，资源和声明跨版改变 | 先切换 64 页，再覆盖脚本 |
| `wide-launch` | 从空站上线 256 页，每页引入一个独立的新脚本 | 256 个资源动作和 256 个页面动作分两波 |
| `late-cycle` | 两版各有 384 页，清单最后一页与原路径覆盖的脚本互相等待 | 可排序前缀含 383 页，冲突环返回 3 个节点（含重复起点），退出码 1 |
| `bootstrap-upgrade` | 24 页从 Bootstrap 5.3.2 切到 5.3.3，每页使用未改动的上游 CSS 和 JS bundle，采用版本化资产路径 | 先上传 2 个资产，再切换 24 页，共 48 条约束 |

Bootstrap 组下载两个公开发行包，核对固定的 SHA-512 后，只读取 `dist/css/bootstrap.min.css` 与 `dist/js/bootstrap.bundle.min.js` 的原始字节。承载它们的 HTML 和其余负载均按固定代码生成。[Bootstrap 5.3.2 包元数据](https://registry.npmjs.org/bootstrap/5.3.2) · [Bootstrap 5.3.3 包元数据](https://registry.npmjs.org/bootstrap/5.3.3)

`--checkpoint` 另外测量 0.8.0 的实际部署检查。在 Bootstrap 负载上把两个新版资源和前 12 页复制到旧站形成中间状态。以同一份 14 步日志，分别执行单独检查顺序，以及检查顺序并核对本地部署目录。两次均应返回 `partial`、14/26 步和相同的 12 个就绪页面，现场校验还须返回 28 条路径全部匹配。计时包含两份快照的重新读取与建图，创建中间状态及准备日志发生在计时前。

## 纯 MoonBit 日志回放

```sh
moon bench rollout --release --target js
moon bench rollout --release --target wasm
```

从 0.8.0 起可单独测量回放库。每条独立依赖链包含 16 页、16 个资源动作，共 32 波。日志先走完一条链上的全部 32 个动作，再开始下一条链，跨越规划器的波次边界。测量从建立回放状态到确认日志全部完成，计划和日志在计时开始前构造。[基准源码](../rollout/replay_bench_test.mbt)
