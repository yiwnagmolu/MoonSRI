# 完整发布日志与现场核查的端到端基准

这组基准测量同一版本的三个 CI 操作。规划读取两份构建并计算依赖图。完整日志检查再验证每一个文件动作。现场核查还从独立部署目录读取文件，比较它们与相应构建版本的 SHA-384 摘要。共享脚本案例额外模拟了一处实际字节漂移。

### 测试输入

| 输入 | 部署状态与预期结果 |
| --- | --- |
| 仓库门店示例 | `examples/rollout/before` 到 `versioned`，使用仓库的四步跨波次日志。独立现场目录保留旧脚本，两页和四个资源均应匹配。 |
| 共享 512 KiB 脚本的 64 页站点 | 同一个脚本路径在两版间原地替换。每页重复引用两次，旧页仅接受旧摘要，新页同时接受新旧两种 SHA-512 摘要。完整日志先切换 64 页，最后替换脚本，现场共核查 65 个文件。 |
| 共享脚本漂移 | 复制完整部署，用异或修改共享脚本的最后一个字节，保持文件长度不变。预期命令返回 1，日志仍为 `complete`，现场报告唯一的 `target/different`，其余 64 页均匹配。 |

### 环境与计时

脚本先构建 release CLI，将独立的现场目录按日志逐步从旧版推进到新版。所有准备工作在计时前完成。每种模式预热一次，此后轮换各模式的启动顺序。每个样本都启动一个新的 CLI 进程，计时自启动前开始，至进程退出且 JSON 输出读取完毕结束。退出码与输出内容校验在停止计时后执行。文件系统缓存随预热自然保留。

脚本逐次核验波次数量、约束数、动作总数、日志完成状态、现场检查数和具体差异，并校验同一案例和模式在不同样本及后端产生相同的 JSON 字节。[0.9.0 原始样本与环境](checkpoint-results-0.9.0.json)（从 `v0.9.0` 标签构建）· [2026-11-24 的 0.8.0 测量](checkpoint-results.json)

### 复现

本机每种模式独立运行五次，表中为中位数，单位为毫秒。

| 站点 | 后端 | 仅规划 | 完整日志 | 日志及现场核查 | 现场一字节漂移 |
| --- | --- | ---: | ---: | ---: | ---: |
| 两页门店 | JS | 163.4 | 166.8 | 169.5 | — |
| 两页门店 | Wasm-GC | 61.0 | 61.3 | 67.4 | — |
| 64 页共享脚本 | JS | 219.3 | 220.8 | 249.7 | 255.4 |
| 64 页共享脚本 | Wasm-GC | 896.6 | 886.8 | 1717.3 | 1728.9 |

两组负载均按预期完成。额外读取 65 条现场路径后，共享脚本负载在 Wasm-GC 上约需 1.72 秒。单字节漂移得到一条定位到共享脚本的差异记录。

在仓库根目录使用 Python 3.10 及以上版本运行。需要 `moon`、`moonrun`、`git` 和 Node.js。共享脚本由固定字节序列生成，两个站点均在本地构造。不传 `--revision` 时测量当前工作树。

```sh
python -B benchmarks/checkpoint.py --revision v0.9.0 --samples 5 --out checkpoint-local.json
```
